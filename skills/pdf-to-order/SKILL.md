# PDF to Order - PDF 報價單轉訂單

## AI 行為指引

### 🚨 重要：如何偵測 LINE 媒體附件

**當你看到用戶訊息包含 `<media:document>` 標記時，立即執行以下步驟：**

#### 步驟 1：提取 messageId

用戶訊息格式範例：
```
[LINE user:Uxxxx +27s 2026-02-05 13:03 GMT+8] <media:document>
[message_id: 599678957213712385]
```

從 `[message_id: xxx]` 提取 messageId（例如：`599678957213712385`）

#### 步驟 2：呼叫 pdf-to-order skill

使用 exec 工具執行：
```bash
cd ~/clawd/skills/pdf-to-order && \
node index.js "<media:document> [message_id: 599678957213712385]" '{"messageId":"599678957213712385","channel":"line"}'
```

**重要：** 將整個用戶訊息（包含 `<media:document>` 標記和 messageId）作為第一個參數傳遞。

#### 步驟 3：解讀回應並轉達用戶

Skill 會回傳以下格式之一：

**情況 A：詢問用戶意圖**
```
📄 已收到 PDF 文件

請選擇要執行的動作：

1️⃣ 截取文字回傳
2️⃣ 建立採購單
3️⃣ 建立銷貨單

請回覆數字（1、2 或 3）
```

**情況 B：直接解析並顯示確認**
```
✅ 已解析以下資訊：

👤 供應商：百凌工业股份有限公司
📦 品項：
  • PRO-183 × 30 @ $500 = $15,000
💰 總額：$15,000

請確認是否要建立採購單？
回覆「確認」繼續，「取消」取消。
```

**情況 C：錯誤**
```
❌ 無法下載 PDF 文件
❌ 無法讀取 PDF 內容
❌ 無法從 PDF 中解析訂單資訊
```

#### 步驟 4：處理用戶回覆

- 如果用戶選擇意圖（1/2/3）→ 再次呼叫 skill 並傳遞選擇
- 如果用戶確認建單 → 呼叫 create-order skill
- 如果用戶取消 → 回覆「已取消」

### 何時啟動此 Skill

| 情況 | 觸發條件 | 動作 |
|------|---------|------|
| LINE 上傳文件 | 訊息包含 `<media:document>` | 立即呼叫 |
| 指定檔名 | 訊息提到 `.pdf` 檔案 | 呼叫並傳檔名 |
| 用戶說「根據這份...」 | 指向先前上傳的文件 | 使用記憶中的 messageId |

### 何時不要啟動
- PDF 明顯不是訂單相關文件（例如：說明書、合約、發票掃描件）
- 用戶在討論 PDF 但沒有上傳文件
- 訊息包含 `<media:image>` 或其他非文件媒體

### ⚠️ 檔案格式限制

**此 Skill 只支援 PDF 格式！**

- ✅ 支援：`.pdf` 文件
- ❌ 不支援：`.xlsx`, `.docx`, `.txt`, `.zip` 等其他格式

**如果用戶上傳非 PDF 文件：**
```
❌ 檔案格式不支援

此功能目前只支援 PDF 格式的報價單。

請：
1️⃣ 將文件轉存為 PDF 後重新上傳
2️⃣ 或使用「手動輸入」方式建立訂單

💡 提示：Excel/Word 可以「另存新檔 → PDF」
```

### 核心流程

**情況 A：無明確意圖**
```
偵測 PDF → 下載 → 提取文字 → 詢問用戶意圖 → 根據選擇執行
```

**情況 B：有明確意圖**
```
偵測 PDF + 意圖關鍵詞 → 下載 → 提取文字 → 直接執行對應動作
```

### 支援的意圖

| 意圖 | 關鍵詞 | 動作 |
|------|--------|------|
| 截取文字 | 截取、提取、extract、文字 | 只回傳 PDF 文字內容 |
| 建立採購單 | 採購、購買、我要買、purchase | 解析 → 建立 PUR- 訂單 |
| 建立銷貨單 | 銷貨、報價、賣、sales、quotation | 解析 → 建立 ORD- 訂單 |

### AI 角色
- 呼叫 `processPdfOrder(message, context, claudeApi)` 後，系統會自動處理整個流程
- 如果用戶沒有明確意圖，系統會詢問用戶
- 用戶選擇後，使用 `handleUserIntentChoice(choice, state)` 處理
- AI 需要將解析結果傳給用戶確認
- 確認後自動建立訂單

## PDF 解析邏輯

### 1. 下載 PDF
- LINE 訊息包含附件 → 使用 LINE API 下載
- 指定檔名 → 從 `~/clawd/uploads/` 讀取

### 2. 文字提取
使用 `pdf-extract` skill：
```bash
pdf-extract "quotation.pdf"
```

### 3. 資訊提取

| 資訊 | 識別方式 |
|------|---------|
| 供應商名稱 | 抬頭、「供應商」「賣方」欄位 |
| 品號 | PRO-XXX 格式、「品號」「料號」欄位 |
| 品名 | 品號旁邊的描述文字 |
| 數量 | 數字 + 「個」「件」「pcs」單位 |
| 單價 | 「單價」「Price」欄位，金額格式 |
| 總額 | 「總計」「Total」欄位 |

### 4. 訂單類型判斷
- 從供應商 PDF → **採購單（purchase）**
- 給客戶報價 PDF → **銷售單（sales）**

**預設：** 用戶說「我要購買」→ 採購單

| 狀態 | 說明 | 可接受的回覆 |
|------|------|-------------|
| `waitingForUserIntent` | 等待用戶選擇動作 | 1/2/3 或 截取/採購/銷貨 |
| `processingPdf` | 正在下載和解析 PDF | （自動執行） |
| `waitingForOrderConfirmation` | 等待用戶確認訂單資訊 | 確認/取消 |
| `creatingOrder` | 正在建立 ERP 訂單 | （自動執行） |

## 錯誤處理

| 情況 | 系統回覆 |
|------|---------|
| 未偵測到 PDF | 「未偵測到 PDF 文件。請上傳 PDF 或指定檔名。」 |
| PDF 下載失敗 | 「無法下載 PDF 文件，請稍後再試。」 |
| PDF 提取失敗 | 「無法讀取 PDF 內容，請確認文件格式。」 |
| 無效的選擇 | 「無效的選擇。請回覆 1、2 或 3。」 |
| 狀態過期 | 「狀態已過期，請重新上傳 PDF。」 |
| 解析失敗 | 「無法從 PDF 中解析訂單資訊。請手動輸入。」 |
| 找不到供應商 | 轉交給 create-order 的「客戶不存在」流程 |
| ERP 連接失敗 | 「無法連接 ERP 系統。請稍後再試。」 |

## 常見錯誤（Anti-patterns）

- ❌ **不要** 在用戶只是上傳 PDF 但沒說要買時自動啟動
- ❌ **不要** 跳過確認步驟 — 必須讓用戶檢查解析結果
- ❌ **不要** 在解析失敗時強制建單 — 提供手動輸入選項
- ✅ **一定要** 顯示完整解析結果給用戶確認
- ✅ **一定要** 判斷正確的訂單類型（purchase vs sales）
