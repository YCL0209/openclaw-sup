# PDF to Order - 功能演示

## ✅ 已完成的更新

### 新功能：智能意圖詢問

當用戶上傳 PDF 時，系統會自動詢問用戶想要執行的動作：

1. **截取文字回傳** - 只提取 PDF 內容
2. **建立採購單** - 從供應商報價單建立採購訂單
3. **建立銷貨單** - 從客戶詢價建立銷售訂單

---

## 🎯 互動流程

### 流程圖

```
用戶上傳 PDF
    ↓
偵測意圖關鍵詞？
    ├─ 有 → 直接執行
    └─ 無 → 詢問用戶
         ↓
    選擇 1/2/3
         ↓
    執行對應動作
```

---

## 💬 實際對話範例

### 範例 1：系統詢問（無意圖關鍵詞）

```
📱 [上傳 quotation.pdf]

🤖 📄 已收到 PDF 文件：quotation.pdf

請選擇要執行的動作：

1️⃣ 截取文字回傳
   → 只提取 PDF 文字內容

2️⃣ 建立採購單
   → 從 PDF 解析品項並建立採購訂單（PUR-）

3️⃣ 建立銷貨單
   → 從 PDF 解析品項並建立銷售訂單（ORD-）

請回覆數字（1、2 或 3）或關鍵詞（截取/採購/銷貨）
```

## 🔧 技術實現

### 新增函數

1. **`detectUserIntent(message, context)`**
   - 偵測訊息中的意圖關鍵詞
   - 返回：`'extract'` / `'purchase'` / `'sales'` / `null`

2. **`formatIntentQuestion(pdfPath, pdfText)`**
   - 生成意圖詢問訊息
   - 包含三個選項的說明

3. **`executeIntent(intent, pdfPath, pdfText, message)`**
   - 根據意圖執行對應動作
   - `extract` → 回傳文字
   - `purchase` → 建立採購單
   - `sales` → 建立銷貨單

4. **`handleUserIntentChoice(choice, state)`**
   - 處理用戶的選擇回覆
   - 支援數字（1/2/3）和關鍵詞

5. **`formatExtractedText(pdfText)`**
   - 格式化提取的文字
   - 超過 2000 字元會截斷

### 新增狀態

- **`waitingForUserIntent`**
  - 等待用戶選擇動作
  - 儲存 `pdfPath` 和 `pdfText`

## 🧪 測試案例

### 測試 1：基本詢問流程

1. 上傳 PDF（無關鍵詞）
2. 收到意圖詢問
3. 回覆「2」
4. 進入採購單確認
5. 回覆「確認」
6. 建立 PUR- 訂單

### 測試 2：關鍵詞跳過

1. 上傳 PDF + 「我要購買」
2. 跳過詢問
3. 直接進入採購單確認

### 測試 3：截取文字

1. 上傳 PDF
2. 回覆「1」
3. 只回傳文字內容
4. 不建立訂單

### 測試 4：錯誤輸入

1. 上傳 PDF
2. 回覆「abc」
3. 收到錯誤提示
4. 重新回覆「2」
5. 正常執行
