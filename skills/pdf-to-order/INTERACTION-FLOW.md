# PDF 上傳互動流程說明

## 🎯 設計理念

當用戶上傳 PDF 時，系統不會「猜測」用戶的意圖，而是明確詢問，提供三種選擇：

1. **截取文字** - 只提取 PDF 內容，不建立訂單
2. **建立採購單** - 從供應商報價單建立採購訂單（PUR-）
3. **建立銷貨單** - 從客戶詢價建立銷售訂單（ORD-）

---

## 📊 完整流程圖

```
用戶上傳 PDF
    ↓
系統偵測 PDF
    ↓
檢查訊息是否包含意圖關鍵詞？
    ├─ 是 → 直接執行對應動作
    └─ 否 ↓
         詢問用戶意圖
         （顯示 3 個選項）
              ↓
         用戶選擇（1/2/3）
              ↓
    ┌─────────┼─────────┐
    │         │         │
   1️⃣        2️⃣        3️⃣
截取文字   建立採購   建立銷貨
    ↓         ↓         ↓
 回傳文字   解析訂單   解析訂單
            ↓         ↓
         確認流程   確認流程
            ↓         ↓
        建立 PUR-  建立 ORD-
```

## 💬 實際對話範例

### 情境 1：無意圖關鍵詞（詢問模式）

```
👤 用戶：[上傳 quotation.pdf]

🤖 系統：
📄 已收到 PDF 文件：quotation.pdf

請選擇要執行的動作：

1️⃣ 截取文字回傳
   → 只提取 PDF 文字內容

2️⃣ 建立採購單
   → 從 PDF 解析品項並建立採購訂單（PUR-）

3️⃣ 建立銷貨單
   → 從 PDF 解析品項並建立銷售訂單（ORD-）

請回覆數字（1、2 或 3）或關鍵詞（截取/採購/銷貨）
```

---

```
👤 用戶：1

🤖 系統：

━━━━━━━━━━━━━━━━
百凌工业股份有限公司

━━━━━━━━━━━━━━━━
```

```
請確認是否要建立採購單？
回覆「確認」繼續，「取消」取消。

👤 用戶：確認

🤖 系統：
✅ 採購單建立成功！
📋 PUR-260205-XXXX
👤 供應商：百凌工业股份有限公司
```

## 🎯 意圖關鍵詞對照表

| 意圖 | 關鍵詞 | 數字選項 |
|------|--------|---------|
| 截取文字 | 截取、提取、extract、文字 | 1 |
| 建立採購單 | 採購、購買、我要買、purchase | 2 |
| 建立銷貨單 | 銷貨、報價、賣、sales、quotation | 3 |

## 🔄 狀態管理

### State 1: `waitingForUserIntent`

**觸發條件：** 上傳 PDF 但無意圖關鍵詞

**儲存狀態：**
```json
{
  "pdfPath": "/Users/xxx/clawd/uploads/quotation.pdf",
  "pdfText": "百凌工业股份有限公司\n報價單\n..."
}
```

**可接受輸入：**
- `1` / `2` / `3`
- `截取` / `採購` / `銷貨`
- `提取` / `購買` / `報價`
- `extract` / `purchase` / `sales`

**錯誤處理：**
- 其他輸入 → 回覆「無效的選擇。請回覆 1、2 或 3。」

---

### State 2: `waitingForOrderConfirmation`

**觸發條件：** 選擇建立訂單（2 或 3）且解析成功

**儲存狀態：**
```json
{
  "pdfPath": "...",
  "orderInfo": {
    "orderType": "purchase",
    "customerName": "百凌工业股份有限公司",
    "items": [...],
    "totalAmount": 15000
  }
}
```

**可接受輸入：**
- `確認` / `yes` / `y` / `是`
- `取消` / `no` / `n` / `否`

## ⚠️ 錯誤處理

### 無效選擇

```
👤 用戶：abc

🤖 系統：
❌ 無效的選擇。請回覆 1、2 或 3。
```

### 狀態過期

如果用戶等太久才回覆，狀態可能已清除：

```
👤 用戶：2

🤖 系統：
❌ 狀態已過期，請重新上傳 PDF。
```

### PDF 解析失敗

```
👤 用戶：2

🤖 系統：
❌ 無法從 PDF 中解析訂單資訊。

可能原因：
1. PDF 格式不是報價單
2. 表格結構無法識別
3. 文字提取失敗

請手動輸入訂單資訊。
```

## 💡 使用建議

### 給一般用戶

- 不確定要做什麼 → 直接上傳 PDF，系統會問你
- 知道要建採購單 → 上傳時說「我要購買」，省一步
- 只想看內容 → 選擇「1」或說「截取文字」

### 給進階用戶

直接用關鍵詞，跳過選擇步驟：
- 「這份我要購買」→ 直接建採購單
- 「幫我報價」→ 直接建銷貨單
- 「提取這份文字」→ 直接截取文字

## 🧪 測試案例

### 測試 1：基本流程

```bash
1. 上傳 PDF
2. 系統詢問意圖
3. 回覆「2」
4. 檢查是否顯示採購單確認
5. 回覆「確認」
6. 驗證 PUR- 訂單建立成功
```

### 測試 2：帶關鍵詞

```bash
1. 上傳 PDF + 「這份我要購買」
2. 檢查是否跳過意圖詢問
3. 直接進入採購單確認
4. 回覆「確認」
5. 驗證訂單建立
```

### 測試 3：截取文字

```bash
1. 上傳 PDF
2. 回覆「1」
3. 檢查是否只回傳文字
4. 不應建立訂單
```

### 測試 4：錯誤處理

```bash
1. 上傳 PDF
2. 回覆「abc」
3. 檢查錯誤提示
4. 回覆「2」
5. 正常執行
```
