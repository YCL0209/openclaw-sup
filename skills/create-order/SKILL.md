# Create Order - ERP 訂單建立

## AI 行為指引

### 何時啟動此 Skill
- 用戶明確表達要「建立新訂單」的意圖
- 關鍵詞：建立訂單、下單、訂購、我要訂、建單、開訂單、幫我訂、order、新訂單
- **採購相關：** 我要買、採購、建立採購單、purchase
- 用戶提供了客戶名稱 + 品項資訊

### 何時不要啟動
- 用戶只是查詢訂單狀態（例如：「ORD-260123 的狀態？」）
- 用戶要修改已存在的訂單
- 用戶問價格但沒有要下單
- 對話中提到「訂」但不是要建立訂單（例如：「我訂閱了」「預訂時間」）
- 用戶要「生成/列印」已存在訂單的 PDF → 應啟動 generate-pdf
  - 注意區分：「建立採購單」= 建立新訂單（本 skill），「生成採購單 PUR-xxx」= 生成 PDF（generate-pdf）

### 核心流程
```
解析用戶訊息（含訂單類型） → 查詢 ERP 客戶 → 顯示確認 → 用戶確認 → 建立訂單
```

### AI 角色
- 呼叫 `createOrder(message, context, claudeApi)` 後，系統會自動處理整個流程
- AI 只需要把系統回傳的訊息傳給用戶
- 不需要手動呼叫 ERP API，index.js 已處理所有認證和 API 調用

---

## 訂單類型（重要！）

系統支援兩種訂單類型，由用戶訊息中的關鍵詞決定：

| 類型 | orderType | 訂單編號格式 | 觸發關鍵詞 |
|------|-----------|-------------|-----------|
| 銷售單 | `sales` | `ORD-YYMMDD-XXXX` | 下單、訂購、我要訂、賣（預設） |
| 採購單 | `purchase` | `PUR-YYMMDD-XXXX` | 我要買、採購、建立採購單、purchase、買 |

**規則：** 用戶訊息含「採購」「我要買」「purchase」「買」→ `orderType: purchase`，否則 → `orderType: sales`

**確認指令：** confirm / yes / y / 是 / 確認
**取消指令：** cancel / no / n / 否 / 取消

### 模式 C：客戶不存在

系統查詢 ERP 找不到客戶時，提供三選一：

```
找不到客戶「陳先生」

請選擇：
1️⃣ 建立新客戶「陳先生」
2️⃣ 重新輸入客戶名稱
3️⃣ 取消
```

- 選 1：系統直接建立新客戶，然後繼續訂單確認流程
- 選 2：請用戶重新輸入客戶名稱
- 選 3：取消整個流程

### 模式 D：解析失敗

當系統無法理解訂單內容（confidence < 0.5）：

```
無法理解訂單內容。請提供：客戶名稱、品項和數量。
範例："/order 王小明 A產品x2 B產品x1"
```

## 品項格式

| 格式 | 範例 | 結果 |
|------|------|------|
| 品號+數量 | `PRO-183 數量30` | PRO-183, 數量:30 |
| 品名x數量@單價 | `A產品x2@500` | A產品, 數量:2, 單價:500 |
| 品名x數量 | `A產品x2` | A產品, 數量:2, 價格:0（待補） |
| 數量+品名 | `2個A產品` | A產品, 數量:2, 價格:0 |

**品號格式：** `PRO-NNN`（如 PRO-183）是完整品號，不要拆開解析。

**多品項：** 用逗號分隔，例如 `A產品x2@500, B產品x1@300`

**價格為 0 時：** 訂單會標記「待補價格」，可稍後在 ERP 系統中補填。

## 客戶比對邏輯

系統按以下順序比對 ERP 客戶：
1. 名稱完全匹配
2. 聯絡人完全匹配
3. 名稱部分匹配（包含關係）

## 錯誤回應

| 情況 | 系統回覆 |
|------|---------|
| 訊息無法解析 | 「無法理解訂單內容。請提供：客戶名稱、品項和數量。」 |
| ERP 無法連接 | 「無法連接 ERP 系統。請稍後再試。」 |
| 建立客戶失敗 | 「建立客戶失敗：{錯誤訊息}」 |
| 建立訂單失敗 | 「建立訂單失敗：{錯誤訊息}」 |
| Token 過期 | 自動刷新，用戶不會看到 |

## 常見錯誤（Anti-patterns）

- ❌ **不要** 在用戶說「生成採購單 PUR-xxx」時啟動 — 這是 generate-pdf 的工作
- ❌ **不要** 手動呼叫 ERP API — index.js 已處理所有認證和 API 調用
- ❌ **不要** 把 PRO-183 拆成 PRO- 和 183 — 這是完整品號
- ❌ **不要** 在用戶未確認前就建立訂單 — 必須等待明確的「確認」指令
- ✅ **一定要** 偵測 orderType — 含「採購」或「我要買」→ purchase，否則 → sales
- ✅ **一定要** 在訂單建立成功後提示用戶是否生成 PDF

## 快速記憶

- **觸發：** 用戶要「建立新訂單」（銷售或採購）
- **訂單類型：** 含「採購」或「我要買」→ purchase（PUR-），否則 → sales（ORD-）
- **流程：** 解析（含 orderType）→ 查客戶 → 確認 → 建立
- **狀態機：** `waitingForConfirmation`（等待確認）、`waitingForCustomerChoice`（客戶選擇）
- **成功後：** 詢問是否立即生成 PDF
- **價格可選：** 品項可以不填價格，標記為 0 待補
- **品號格式：** PRO-NNN 是完整品號，不可拆開
- **區分本 skill 和 generate-pdf：** 「建立/買」= 新訂單（本 skill），「生成/列印」已有訂單 = PDF（generate-pdf）
